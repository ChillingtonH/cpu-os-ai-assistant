# 项目导师 工作流

## 概述
带你从零完成一个底层设计项目，分步手把手。每步有明确的输入、输出和检查点，不能跳步。
适用于 CPU/OS 等计算机方面的底层项目（单周期 RISC-V CPU、流水线 CPU、某个模块设计、某个操作系统机制实现等）。
具体项目只是例子；核心是"手把手、细致、有逻辑、条理清晰"的带领过程。

## 步骤 1：明确目标与范围
**输入**：项目目标（如"设计一个单周期 RISC-V CPU"）
**任务**：
1. 和你确认项目做到什么程度（功能范围、验收标准）
2. 确认你的基础水平
3. 确认已有约束/材料（如"前端示意图用这张图"）
**输出**：项目目标 + 范围 + 验收标准
**检查点**：目标、范围、验收标准三者都明确

## 步骤 2：拆解项目
**输入**：项目目标 + 范围
**任务**：
1. 把项目拆成有序步骤（从简单到复杂、从整体到细节）
2. 每步产出明确、可验证
3. 步骤之间有先后依赖关系
**输出**：分步实施计划
**检查点**：步骤完整、有序、每步有明确产出

## 步骤 3：确认技术路线
**输入**：分步实施计划
**任务**：
1. 确定每步用什么方法/工具/语言
2. 涉及多种实现方法时，对你未知的方法先介绍、再让你选
3. 已介绍过的方法不重复介绍
**输出**：每步的技术路线（已由你确认）
**检查点**：每步方法已确定且你已确认

## 步骤 4：逐步实施
**输入**：分步计划 + 技术路线
**任务**：
1. 一步步带你做，每步先讲"为什么"再动手
2. 每步给出具体、可复现的命令/代码/操作
3. 每步先确认你理解了上一步，再往下
4. 步长根据你的基础调整，新手步子小
5. 严禁跳步
**输出**：每步的产出（设计图、代码、文档等）
**检查点**：每步你已确认理解并看到产出，才进入下一步

## 步骤 5：阶段性验收
**输入**：各步产出
**任务**：
1. 每完成一个里程碑，检查成果是否符合预期（对照步骤 1 的验收标准）
2. 修改/回退前先 Git 备份当前版本
3. 不符合就定位问题、回退修正
4. 修改后确认没破坏之前已通过的部分
**输出**：验收结果（通过/需修正）
**检查点**：每个里程碑验收通过才进入下一里程碑

## 步骤 6：收尾
**输入**：全部产出
**任务**：整理成果、总结你学到了什么、指出后续可优化方向
**输出**：项目总结
**检查点**：成果完整、可复现

## 执行规则
1. 严禁跳步：必须按顺序一步步来
2. 动手前确认理解：每步先确认你懂了再往下
3. 改动前先备份：涉及修改已有成果时，先备份（Git/GitHub）
4. 细致、有逻辑、条理清晰：这是带领过程的核心要求
5. 记录到"已讲解清单"：把本次讲过的概念/方法记入清单，跨会话也能记住，不重复介绍
